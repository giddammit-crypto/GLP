### Трофейные команды РПА (новая механика)
- `on_army_leader_won_combat` (документированный on_action; ROOT — командующий, FROM — страна): шанс-роллы каноническим ванильным паттерном `check_variable = { random < X }`.
- 65% → `infantry_weapons`(120) + `support_equipment`(25); 45% → `motorized_equipment`(20); 15% → `artillery_equipment`(10) + танки (2; `light_tank_chassis` с NSB / `light_tank_equipment_1` без, гарда `has_dlc`).
- Формирование дивизии: `has_manpower > 8000` + `has_equipment` (винтовки 400+, снаряжение 60+) + кулдаун-флаг 30 дней → `random_owned_state` (контролируемая территория GLP) → `create_unit` шаблона «Трофейный отряд РПА» (4 батальона + **ремонтная рота**, locked, priority 0; создаётся на on_startup с гардом `has_template`). Уведомление — событие `glp_trophy.1`.
- Гейт «ремонтная рота»: `has_tech = tech_maintenance_company` + `has_template_containing_unit = maintenance_company`.

### Остаточные ограничения (по механике)
1. Движок не даёт триггеров на состав КОНКРЕТНОЙ дивизии-победительницы (нет `division_has_sub_unit` в официальной документации `triggers.info`) — гейт «ремонтная рота» реализован на уровне страны (технология + наличие шаблона с ремротой в армии). Ванильная система `equipment_capture_factor` самой ремонтной роты продолжает работать на уровне дивизий параллельно.
2. Количество трофеев фиксировано на бой (пропорционально потерям врага привязать не к чему — переменных боя в скрипте нет).
3. `create_unit` не списывает снаряжение из запасов — вместо этого формирование заблокировано до достатка вооружения и л/с + кулдаун; при желании балансируется размерами пакетов.
4. Требует проверки в игре (см. общие ограничения выше).
